# 06 — The Web UI

`http://vision:8080` (over Tailscale).

## Pages

- **Live** — grid of all cameras with bounding boxes overlaid, FPS counter,
  per-camera inference latency.
- **Tracks** — recent track list, click to see all clips for a given track ID.
- **Search** — natural-language search powered by CLIP embeddings.
  Examples:
  - *"a person carrying a package"*
  - *"a white truck in the driveway at night"*
  - *"a dog on the grass"*
- **Events** — chronological event log (new track detected, person dwelled
  > 30s, vehicle entered zone, etc.).
- **Settings** — class filters, detection thresholds, retention policy.

## How CLIP search works

For every keyframe selected by the pipeline (default: 1 / second when an
object is being tracked) we:

1. Crop the tracked object's bbox (with a small padding).
2. Run the crop through CLIP's image encoder on Hailo → 512-d embedding.
3. Store the embedding in `events.db` alongside the snapshot path.

When you search:

1. The query text goes through the CLIP text encoder (CPU, ~30ms).
2. We compute cosine similarity vs. every stored image embedding.
3. Top-K results are returned, sorted by similarity.

For our scale (≤100k embeddings) brute-force numpy is fine and fast.
Above that, swap in FAISS — see `app/storage/embedding_index.py`.

## Keyboard shortcuts

- `g` then `l` — Live
- `g` then `s` — Search
- `/` — focus search box
- `space` — pause/resume the live grid
